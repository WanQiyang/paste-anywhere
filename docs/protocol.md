# 剪贴板同步协议 v1

## HTTP 与身份

公网部署使用 HTTPS；本地开发通过 loopback / HDC 隧道使用 HTTP。设备连接后使用 `Authorization: Bearer <token>`，邀请码仅用于创建新的设备凭证。服务端只保存邀请码和凭证的 SHA-256 摘要。

新建用户生成 8 位随机配对码（大写字母 A–Z、数字 2–7，区分大小写）。连接接口仅接受 8 位配对码。`user reset` 原子更换配对码并撤销该用户全部设备，保留账号和在线内容。设备 token 为 64 位十六进制字符串。

用户名和新配对设备名仅允许英文字母、数字，长度 1–128，区分大小写。用户名全局唯一，同一用户下设备名唯一。配对时设备名重复返回 409；名称格式错误返回 400；配对码不存在返回 401。管理 CLI 使用用户名和 `用户名-设备名`；HTTP API 及数据库继续使用内部 ID 保持同步协议稳定。

用户和条目 ID 在 JSON 中编码为十进制字符串，避免 ArkTS/JavaScript 整数精度丢失；设备与附件 ID 为随机十六进制字符串。`createdAt` 为 Unix 毫秒。

| 方法 / 路径 | 请求 | 响应 |
| --- | --- | --- |
| GET `/healthz` | 无鉴权 | `{ "status": "ok" }` |
| POST `/v1/devices` | JSON `{ "invite": "...", "deviceName": "..." }` | 201，`{ device: {id,userId,name}, user: {id,name}, token }`；Location 为设备资源路径 |
| DELETE `/v1/devices/{用户名}-{设备名}` | 当前设备鉴权，无请求体 | 204，撤销当前设备并关闭其连接，释放设备名；只允许删除当前凭证所属设备，其他设备返回 403 |
| GET `/v1/users` | 设备鉴权 | 所有用户的 `{id,name,onlineDevices}` 数组，按设备 ID 去重统计活跃 WebSocket，在线数大于 0 即在线 |
| GET `/v1/entries` | 设备鉴权，可选 `?limit=5` 或 `?limit=1` | 自己的有效记录数组，ID 降序，空时 `[]`；数量不超过服务配置，limit 必须是正整数 |
| POST `/v1/entries` | `application/json` 的 `{ "text": "..." }`，或 `image/png` / `image/jpeg` 原始二进制 | 201，新条目；Location 为条目资源路径 |
| DELETE `/v1/entries` | 当前设备鉴权 | 清空当前账号全部内容及历史，200 返回 `clipboard.cleared` 事件 |
| GET `/v1/entries/{id}` | 设备鉴权 | 仅能读取自己的条目 |
| GET `/v1/entries/{id}/content` | 设备鉴权 | 文本为 `text/plain; charset=utf-8`，图片为原始 PNG/JPEG，支持 Range |
| POST `/v1/transfers` | JSON `{ "entryId": "源条目ID", "userId": "接收者ID" }` | 201，在接收者账户下创建新条目，源条目保留 |

所有 JSON 请求明确设置 `Content-Type: application/json`；图片上传声明的 MIME 必须与实际文件格式一致。不支持的或缺失的上传 Content-Type 返回 415。查询最新内容使用 `GET /v1/entries?limit=1`。

条目结构：

```json
{
  "id": "42",
  "userId": "1",
  "senderId": "2",
  "sourceDeviceId": "随机设备ID",
  "kind": "text",
  "text": "示例文本",
  "createdAt": 1794390000000
}
```

图片条目的 `kind` 为 `image`，`text` 为空，增加如下附件元数据：

```json
{
  "attachment": {
    "id": "随机附件标识",
    "name": "image.png",
    "mime": "image/png",
    "size": 12345,
    "width": 800,
    "height": 600
  }
}
```

附件没有公开静态 URL，必须通过拥有该条目的用户凭证下载。转发创建新条目 ID，复用原附件文件，仅支持图片。

错误为 `{ "error": "说明" }`。401 表示凭证无效，404 表示不可访问或过期条目/目标不存在，400 表示输入无效，413 表示图片字节超限，415 表示不支持的图片格式，500 表示服务端故障。

默认文本上限为 1 MiB UTF-8 字节，图片上限 16 MiB，历史保留 20 条/7 天，可通过 `-max-text`、`-max-image`、`-history`、`-retention` 调整。当前客户端图片上限固定 16 MiB。图片最大 4000 万像素，服务端检查格式、尺寸和完整解码后再入库；图片解码串行执行以限制峰值内存。文本保留空格和换行，不接受空字符串。

图片保存在 `<数据库路径>.attachments/`，数据库的 `blobs`、`entry_files` 表记录元数据与引用。历史超限/过期或用户删除后，清理任务只删除不再被任何条目引用的附件；崩溃遗留的孤立文件超过 1 小时后清理。备份当前格式的数据时需同时保存数据库及附件目录。

Windows 发送快捷键及手动复制读取现有剪贴板，将位图编码为 PNG，也支持已复制的单个 PNG/JPEG 文件；不模拟复制，不自动监听上传。鸿蒙将 PixelMap 编码为 PNG，图片文件保留 PNG/JPEG 原字节，其余可解码格式转换为质量 95 的 JPEG（不保留动画/透明通道）。图片卡片仅显示 `<图片>`，鸿蒙主动预览、复制或分享时下载缓存；清理超过 7 天或最近 20 个以外的缓存，保留当前图片及 5 分钟内新文件。

## 实时通知

以设备鉴权连接 `GET /v1/events`，协议升级为 WebSocket。服务端登记订阅后先发送：

```json
{ "type": "ready" }
```

之后仅推送在线期间发生的更新：

```json
{ "type": "clipboard.updated", "itemId": "42", "sourceDeviceId": "设备ID" }
```

清空通过 `DELETE /v1/entries` 发起，返回并向当前账号所有在线设备（包括来源设备）通知：

```json
{ "type": "clipboard.cleared", "itemId": "42", "sourceDeviceId": "设备ID" }
```

这里 `itemId` 是清空事务时的全局自增序列截止值，不是待下载条目。客户端只移除 ID 小于等于截止值的内容，忽略这些条目的晚到响应及尚未完成的自动剪贴板写入；更大 ID 的新内容不受影响。清空不修改本机系统剪贴板，不删除其他用户已收到的转发副本。附件依引用关系由定时清理任务回收。

- 按接收用户隔离，上传来源设备不推送；发送给其他用户不会更新发送者的剪贴板。
- 条目提交、通知发布和订阅登记串行化；无离线回放、无客户端 cursor 参数。
- 客户端按 ID 去重，收到更大 ID 后旧下载不得覆盖新内容；相同账户重连保留本次进程的水位。
- Windows 收到在线通知才自动下载并写本地剪贴板。启动/重连及 GUI 可见时查询最近 5 条仅用于预览，不触发图片下载或剪贴板写入。
- 手机仅前台连接，`ready` 后查询最近 5 条，后台关闭连接。只有主动复制才写手机剪贴板。
- 在线用户列表和最近 5 条在 GUI 可见/前台期间每 5 秒刷新；通知、上传、转发成功后立即刷新。自己永远排第一，其余过滤 onlineDevices>0 后按用户名排序。用户的多个设备连接聚合成一张卡片；账号标识旁用阿拉伯数字显示该用户的 onlineDevices，同一设备多个连接不会重复计数。最后一个连接关闭后变为离线，异常断线可能需等待心跳超时才被发现。
- 通知下载失败保留本地剪贴板，可打开界面点击卡片重试复制；不保证掉线、过载期间投递。慢客户端队列满时关闭连接，不补发。
- 鸿蒙 API 26 使用 `supportOriginPort: true`，避免 Origin 丢失非默认端口；服务端执行标准同源校验。
- 服务端每 20 秒检查已连接设备凭证并发送 ping，等待响应最多 5 秒。CLI 撤销设备后 HTTP 立即拒绝，已有 WebSocket 最迟在下次检查时关闭；客户端通过 `DELETE /v1/devices/{用户名}-{设备名}` 登出则立即注销当前设备的所有订阅。路径大小写必须与配对身份一致，不能使用当前凭证删除另一台设备；服务端按内部设备 ID 执行删除，防止同名设备重建后的误删。
- Windows 使用 DPAPI 保存设备配置；鸿蒙存储在应用私有 Preferences。邀请码不持久化到客户端。
- 登出成功后清除本地凭证、用户列表及内容预览，返回配对页；凭证已失效的 401 也可清除本机配置。网络失败时保留配置并提示重试，防止丢失凭证却遗留同名设备占位。

## 用户管理

CLI 与服务端使用同一个 SQLite 文件，命令和表格列见 [部署说明](deployment.md)。`user reset` 保留用户身份、创建时间及内容；已有 WebSocket 通过周期性凭证检查关闭，行为与 CLI 删除设备一致。

删除用户同时删除其设备和收到的条目。过去发送给其他用户的条目保留发送者 ID，不联动删除对方内容。删除设备仅撤销该设备凭证，设备名可重新使用。

`user list` 和 `device list` 输出表格，其他管理命令返回 JSON。最近内容时间为未过期保留内容的最大创建时间，不等同于最后活跃时间。

客户端在配对、HTTP 请求及 WebSocket 握手中上报 `X-Paste-Platform`（`Windows` / `HarmonyOS`）及 `X-Paste-Version`（构建版本号）；这两个头可选，不参与鉴权。最近 IP 来自 TCP 对端；配置可信代理模式时读取代理覆盖的 `X-Real-IP`。

只支持空数据库或当前结构（SQLite `user_version=2`），直接创建完整结构，不提供迁移。时间以 Unix 毫秒保存。数据库用 `CHECK` 限制名称格式，`UNIQUE(user_id,name)` 保证设备名唯一。
